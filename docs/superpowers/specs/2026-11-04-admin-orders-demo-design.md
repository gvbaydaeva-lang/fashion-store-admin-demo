# Дизайн отдельной демо-страницы заказов

## Цель

Создать самостоятельную публичную страницу GitHub Pages для показа интерфейса обработки **тестовых** заказов. Это не админка магазина и не подключение к реальным данным.

## Границы

- Репозиторий: `gvbaydaeva-lang/fashion-store-admin-demo`.
- Страница содержит только статические HTML, CSS и JavaScript-файлы.
- На странице всегда виден текст: «Демо-версия. Данные тестовые и не отправляются на сервер».
- В репозитории не будет входа, паролей, passkey, базы данных, API, Telegram, Supabase, Beget, уведомлений или реальных заказов.
- Репозиторий `Tg_katalog`, включая `tg-app/` и `admin-app/`, не изменяется.

## Экран и сценарии

В верхней части размещаются заголовок, предупреждение о демо-режиме и пять фильтров: «Все», «Новые», «В работе», «Собранные», «Отменённые». На кнопках отображаются актуальные счётчики.

Список начинается с фиксированного набора тестовых заказов. У каждой карточки есть номер, имя-заглушка, дата, сумма, текущий статус и кнопка раскрытия состава. Раскрытая карточка показывает тестовые позиции, размер, количество и цену.

Для статусов доступны действия: «Взять в работу», «Собран», «Отменён». После нажатия статус, карточка, активный фильтр и все счётчики обновляются без перезагрузки. Если выбранный фильтр больше не содержит карточку, показывается понятное пустое состояние.

## Хранение данных

Исходные тестовые заказы находятся прямо в JavaScript. Изменённые статусы сохраняются только в `localStorage` браузера под нейтральным ключом. При обновлении страницы они восстанавливаются. Если хранилище недоступно, страница продолжает работать до перезагрузки и объясняет это рядом со списком.

Нет сетевых запросов: JavaScript не использует `fetch`, `XMLHttpRequest`, WebSocket или внешние SDK.

## Адаптивность и доступность

Интерфейс рассчитан на ширины 320, 375 и 430 px, а также на обычный экран компьютера. Кнопки имеют достаточную область нажатия, активный фильтр и статус различимы не только цветом, а раскрытие состава доступно клавиатурой.

## Публикация и проверки

GitHub Actions публикует только содержимое демо-папки в GitHub Pages. Перед публикацией скрипт проверяет, что в доставляемых файлах нет секретоподобных значений и запрещённых ссылок/слов: API, Telegram, Supabase, Beget, базы данных и URL-адресов этих сервисов.

Проверки включают unit-тесты логики статусов и фильтров, статическую проверку запретных строк, `git diff --check`, локальный просмотр на целевых ширинах и HTTP-проверку опубликованной страницы. Проверка на реальном телефоне остаётся отдельным действием владельца устройства: она не может быть подтверждена эмуляцией браузера.
